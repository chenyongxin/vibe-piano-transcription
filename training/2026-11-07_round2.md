# 2026-11-07 Round 2：组合实验（combo 系列 6 组）

## 摘要

本文记录 2026-11-06 深夜到 11-07 上午的 Round 2 训练：在 M3.5 首轮结论的基础上，把「1 帧 onset」「offset 头」「frame_key 数据」组合起来，并做标签宽度、数据增强、随机种子与训练量的对照。读者不需要读过前一份训练报告；读完后能知道最终配方为什么选 combo_base、哪些组合被证明无效、以及为什么 20 轮训练量已经足够。

## 1. 背景与目的

M3.5 首轮（见 [`2026-11-06_m3_5_nightly.md`](2026-11-06_m3_5_nightly.md)）的结论是：

- **A（offset 头）** 是时值方向的最佳单点改进：留出集 note F1 从 0.063 提到 0.268，但开发集 Beethoven 从 0.279 回退到 0.154；
- **B（1 帧 onset）** 把留出集 onset 精确率从 0.860 提到 0.901，但召回率下降；
- **C（数据增强）** 拿到最高的留出集 onset F1（0.878），但开发集 Beethoven onset 回退；
- **D2（只改 frame 口径）** 单独使用不够。

这一轮要回答四个问题：

1. 把 **1 帧 onset + offset 头 + frame_key** 组合起来，能否同时拿到精确率与时值收益？
2. offset 标签的窗口宽度（1 帧 / 2 帧 / 3 帧）哪个最优？
3. 数据增强、训练量加倍、换随机种子，分别会带来什么变化？
4. 放弃 offset 头（只用 frame_key + 1 帧 onset）会损失多少？这是判断 offset 头必要性的对照。

## 4. 观察与分析

**符合预期**：

- **组合有效**：combo_base 同时拿到留出集 note F1 0.372（A 的 0.268）与 onset 精确率 0.924（baseline 的 0.860），说明 1 帧 onset 的去偏收益和 offset 头的时值收益可以叠加。
- **offset 头是必要的**：去掉 offset 损失的 `combo_v3a_onset1` 留出集 note 只有 0.179，几乎是 combo_base 的一半。
- **训练量已饱和**：40 轮的最佳验证 F1 只比 20 轮高 0.0013，且峰值在 85,500 步（约 24 轮）；留出集 note 略高（0.385 vs 0.372），但开发集 note 略低，属于「训练更久没有明确收益」。

**反直觉**：

- **offset 标签 2 帧最优**：改成 1 帧（`combo_offset1`）后留出集 note 掉到 0.251。这和 onset 上「1 帧优于 2 帧」的结论方向相反——同样是「窗口中心偏半帧」，在 onset 上是系统偏差，在 offset 上却是让 offset 头更容易学好的必要冗余。
- **数据增强不叠加**：`combo_aug` 的留出集 note（0.357）低于 combo_base（0.372），onset 也略低；增强带来的泛化收益没有超过它造成的欠拟合。
- **种子方差约 0.02–0.03**：三种子的留出集 note 分别为 0.344 / 0.372 / 0.379，后续选型需要至少 3 个种子。

**可能原因**：

- offset 头部监督本身偏弱（offset 正样本只有约 0.7%），1 帧标签让正样本再减少一半，模型更难学到结束位置；
- 增强的遮蔽比例对 10 秒片段可能过强，抹掉了起音/结束的局部证据；
- 40 轮的后半段训练 loss 继续下降而验证不涨，属于过拟合/饱和。

**另一个影响解读的发现**：解码器当前取「起点后第一个 offset 峰」，对短音会截短、对长音可能取错峰；因此本轮 note 数字主要反映「相对优劣」，绝对上限还要等解码器修复后再评估。

## 5. 下一步猜想（可验证）

| 假设 | 实验设计 | 预期结果 | 成本 |
|---|---|---|---|
| offset 损失权重 1.0 偏小 | combo_base 的 `--offset-loss` 从 1.0 提到 2.0 | 留出集 note 再涨 | 约 1.6 小时 |
| combo 收益需要多种子确认 | 同配方跑 seed 1、2、3 | 方差 < 0.02 | 每组 1.6 小时 |
| 解码器是下一个瓶颈 | 在候选 offset 峰里选与 frame 释放一致的峰 | 修短音截断/长音取错峰 | 约 1 小时，无需训练 |
| Beethoven 是密集曲目的特例 | 按 onset 漏检/时值错误拆分错误类型 | 定位到具体原因 | 约 30 分钟 |

## 6. 结论

本轮确认了 M3.5 的方向：**frame_key + 1 帧 onset + offset 头（2 帧标签）的组合是目前最佳配方**，留出集 note F1 0.372、onset 精确率 0.924，两项都优于之前所有单点方案。offset 标签保持 2 帧；数据增强不叠加；训练量 20 轮已饱和，40 轮没有明确收益。种子方差与解码器的局限说明，下一步应优先做多种子确认与 offset 解码修复，而不是继续加训练量。
