# 训练报告目录

## 这个目录是什么

这里按时间记录**每次大跑**（单次超过 1 小时，或包含多组实验的队列）的完整过程。
它和 `experiments/registry/` 分工不同：

- `experiments/registry/`：给程序与表格用的实验条目（配置、指标、检查点哈希）；
- `training/`：给人读的报告——当时想验证什么、怎么跑、看到了什么、后来怎么判断。

## 报告的结构约定

每份报告按下面的顺序写，**不要开头就下结论**：

1. **摘要**：先交代这篇报告记录了什么、读者需要什么背景（默认读者没读过前一份报告）；
2. **背景与目的**：这次训练之前的事实、想验证的假设、预注册判据；
3. **实验设计 / 配置**：数据版本、模型、超参数、对照关系；
4. **结果**：验证集、开发集、留出集的数字，尽量用表格；
5. **观察与分析**：符合预期与反直觉的地方、可能原因；
6. **下一步猜想**：可验证的假设与实验设计；
7. **结论**：放在文末，总结这次实验确认了什么、推翻了什么；
8. **相关链接**：登记 JSON、文档、日志、检查点。

写每一节时假设读者是第一次读：不要出现「如前所述」「显然」「大家都知道」这类依赖上下文的表达；
文章开头不要出现「本文结论是……」的写法。

## 写作要求

- 英文术语首次出现时给中文对照，例如 CQT（常 Q 变换）、onset（起音）；
- 数字要能追溯到产物（日志、评测 JSON、检查点路径）；
- 结论里的每个判断都要在「结果」或「观察与分析」里有对应证据；
- 图表放在相关段落旁边，不要堆在文末。
