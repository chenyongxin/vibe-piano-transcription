## 3. 观察与分析

- **A（offset 头）方向正确**：留出集 note F1 从 0.063 提到 0.268（约 4.2 倍），
  Haydn、Mozart 也明显上升；验证 F1 为四组最高。说明 offset 监督本身没有破坏学习。
- **A 的异常**：Beethoven note 从 0.279 掉到 0.154，onset 也从 0.820 降到 0.808。
  Beethoven 是密集、和弦多、踏板多的曲目；目前怀疑 offset 峰在密集音群中互相干扰，
  或解码搜索窗/阈值参数不适配，需要用错误分析 + 解码网格搜索确认。
- **B（1 帧 onset）提高精确率**：留出集 precision 0.860 → 0.901，F1 持平；召回率下降
  （0.880 → 0.841）。对起点偏差的分析（同一批开发集，贪心匹配 GT）：
  baseline（2 帧）估计起点中位偏差 **+14.7 ms（Haydn）/ +12.9 ms（Mozart）**；
  1 帧模型为 **-0.5 ms / -1.1 ms**。2 帧标签的中心天然比真实起点晚半帧（16 ms），
  所以 1 帧的收益主要是**去偏**，不是新增信息。
- **第二帧是否能区分「弹没弹下去」**：不能。标签构造上第二帧被强制为正；
  物理上 onset 后 32 ms，frame 标签仍为发声的比例只有 66%–81%
  （Mozart 的 GT 时值 < 64 ms 占 37%，短音在第 2 帧前就结束或轮空），
  也就是说对短音而言，2 帧 onset 标签与 frame 标签存在冲突，相当于给模型加了噪声。
- **C（数据增强）泛化最好但开发集回退**：留出集 onset F1 0.8784 / precision 0.8954 为四组最高，
  但 Beethoven 开发集 onset 掉到 0.798，note 指标不变。
- **D2 单改口径不够**：留出集 note 升到 0.170，但开发集 note 全部下降，说明只对齐标签口径
  而不用显式 offset 事件，结束时间依然不准。

## 4. 下一步猜想（可验证）

| 假设 | 实验设计 | 预期结果 | 成本 |
|---|---|---|---|
| A 的 Beethoven 回退是解码参数问题 | 对 A 模型网格搜索 `offset_threshold` / `offset_min_frames` / `offset_max_frames` | Beethoven note F1 回升 | 约 15 分钟（无需训练） |
| offset 头与 1 帧 onset 可叠加 | data_v3b + `--label-channel onset1` + `--offset-loss 1.0` 训练 20 轮 | onset 精确率 0.90 左右，note F1 不低于 A | 约 1.6 小时 |
| 增强与 offset 可叠加 | 组合实验里加 `--aug-freq-mask/--aug-time-mask` | 留出集进一步提升 | 约 1.6 小时 |
| 谱面可用性 | 应用侧启用 offset 解码，真实曲目听感验证 | 时值听感明显改善 | 约 1 小时 |
