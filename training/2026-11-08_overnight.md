# 2026-11-08 夜间实验：offset 损失权重确认与扫描

## 摘要

本文记录 2026-11-07 夜间的四组训练：在 combo 配方（data_v3b + 1 帧 onset + offset 头）上，复现 offset 损失权重 2.0 并扫描 3.0 / 4.0。读者不需要读过之前的报告；读完后能知道 loss 2.0 的增益是否稳定、权重的最优区间在哪、以及下一步为什么应转向解码器与 Beethoven 错误分析。

## 1. 背景与目的

Round 2 与下午队列已经确定：

- 最佳组合是 **data_v3b（frame_key + offset 2 帧）+ 1 帧 onset + offset 头**；
- 下午的 `combo_offset_loss2`（offset 损失权重 2.0）拿到留出集 note F1 **0.410**，是目前最高；
- 但当时权重 2.0 只有一颗种子，增益（相对权重 1.0 的 0.372）是否只是种子运气还不确定；
- 权重是否还能继续加大（3.0、4.0）也没有数据。

这一轮要回答两个问题：

1. 权重 2.0 的三颗种子结果是否稳定？
2. 权重 1.0 / 2.0 / 3.0 / 4.0 中，哪个区间最优？

## 4. 观察与分析

**符合预期**：

- 权重 2.0 的三颗种子很集中（0.392–0.410，标准差 0.0095），均值 0.403，比权重 1.0 的均值 0.365 高 **0.038**；这是约 4 倍标准误的差距，可以认为**真实有效**，不是种子运气。
- 权重 2.0 的 onset 精确率（0.906–0.926）与权重 1.0 相当，没有明显牺牲起音质量。

**反直觉 / 需要谨慎**：

- 权重 3.0 单次拿到 0.409，与权重 2.0 的均值几乎相同；但它只有一颗种子，不能据此认为 3.0 更好。按当前数据，**2.0 是更稳的选择**（三 seed 均值）。
- 权重 4.0 回落到 0.391，说明「越大约束 offset 头」并不一直有效，权重过高可能压过 frame/onset 的学习。

**可能原因**：

- offset 正样本只有约 0.7%，权重 1.0 时 offset 头监督偏弱；2.0 让 offset 头学得更充分，同时没有明显干扰其他头；
- 继续加到 3–4 时，offset 损失开始主导，密集曲目（Beethoven）的时值反而更难优化。

**仍未解决**：

- 开发集 Beethoven 的 note F1 仍在 0.21–0.23，远低于 Haydn/Mozart；需要错误类型分析；
- 解码器仍取「起点后第一个 offset 峰」，短音截断/长音取错峰的问题没有修，绝对上限可能被它压低；
- 留出集只有一首曲目，方差判断依赖开发集与多 seed。

### 4.1 附加实验：offset 解码规则对比（不重训）

夜里顺手比较了三种结束时间规则（复用 loss2_seed0 / loss3 / A / combo_base 的推理结果，只换解码）：

- `first`：取起点后第一个 offset 峰（当前默认）；
- `guard`：取第一个峰，但若它离 frame 估计结束超过 160 ms，则退回 frame 的结束时间；
- `closest_guard`：在候选峰里选离 frame 结束最近的，超过 160 ms 同样退回。

以 loss2_seed0 为例：

| 曲目 | first | guard | closest_guard |
|---|---|---|---|
| Haydn | **0.328** | 0.233 | 0.230 |
| Mozart | **0.504** | 0.466 | 0.454 |
| Beethoven | 0.215 | **0.305** | 0.293 |
| 留出集 | **0.410** | 0.285 | 0.235 |

结论：**没有一种规则全面占优**。`guard` 把密集曲目 Beethoven 从 0.215 提到 0.305，但 Haydn/Mozart/留出集都明显下降，说明 frame 与 offset 两个头对「结束在哪」的判断冲突时，简单地偏向 frame 会牺牲稀疏曲目。解码器需要更细的混合策略（按曲目密度/音符长度自适应，或调 guard 的容差），不能直接用当前原型替换默认规则。

## 5. 下一步猜想（可验证）

| 假设 | 实验设计 | 预期结果 | 成本 |
|---|---|---|---|
| 解码器是下一步主要瓶颈 | 在候选 offset 峰里选与 frame 释放一致的峰，不重训 | 修短音截断/长音取错峰，note F1 提升 | 约 1 小时，无需训练 |
| Beethoven 有特定错误模式 | 拆分漏检/多检/时值错误，按音区与踏板统计 | 定位到具体原因 | 约 30 分钟 |
| 权重 3.0 与 2.0 无显著差异 | 权重 3.0 再跑 2 颗种子 | 若均值接近 0.403，则保留 2.0 | 2 × 1.6 小时（可选） |
| 组合配方可上应用 | 把 combo_loss2（seed0）接入 Web，启用 offset 解码，人工听感验证 | 时值听感明显改善 | 约 1 小时 |

## 6. 结论

offset 损失权重 **2.0** 是目前最稳的配方：三颗种子的留出集 note F1 为 0.410 / 0.392 / 0.407，均值 **0.403**、标准差 0.0095，明显高于权重 1.0 的 0.365；权重 3.0 的单次 0.409 仍在噪声范围内，4.0 开始回落。训练量 20 轮不变。接下来的优先级应从「继续调权重」转向**解码器修复、Beethoven 错误分析、应用侧验证**，并且暂时不需要 4090。
