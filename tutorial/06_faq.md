# 06 常见问题

## 为什么以前转录出来「黑音符」特别多？

旧版记谱层用固定 120 BPM、把按键秒数直接当时值、每个音单独塞进 music21，导致绝大多数音符是
三十二分音符之类的黑音符。后来换成「拍点估计 → 量化 → 和弦化 → 时值拆分 → 手动建小节」，
黑音符占比从 86–98% 降到 72% 左右。**这不是模型的功劳，是记谱层的修复。**

## holdout（留出集）是什么？

相当于「正式考卷」：调参用开发集（可以反复做），最终只在一批没碰过的曲目上评一次。
如果拿调参数据报成绩，分数会虚高（过拟合）。详见 `../docs/02_data.md`。

## PUA 是什么？为什么节拍记号只剩「=144.23」？

PUA = Unicode 私用区，音乐字体（SMuFL）把谱号、音符头、节拍记号里的四分音符等符号放在这里。
我们用 rsvg 渲染 PNG 时，它不加载 SVG 内嵌的音乐字体，会渲染成乱码大字，所以把这类文本删掉了；
代价是节拍记号里的音符符号也被删掉。**不影响音符与小节**，后续会修。

## 为什么训练变快了？

三个原因叠加：

1. 每段从 65 秒（2048 帧）改成 10 秒（313 帧），注意力计算量随长度平方下降；
2. 数据用 memmap 随机切片，不再每步解压整首歌（155 ms → 1.5 ms/样本）；
3. 标签修好后，达到同样效果需要的步数也少了。

所以旧 4090 两小时（6200 步）↔ 新 4060 十分钟（8000 步）。

## 为什么模型不能直接吃 MP3 / 流行歌？

可以吃 MP3（librosa 会解码），但**只支持独奏钢琴**：训练数据全是钢琴独奏，
多乐器、人声、电音超出训练分布，效果会明显变差。

## 需要什么显卡？没有显卡能跑吗？

- 有 NVIDIA GPU 最快（4060 上 65 秒音频约 4 秒出谱）；
- 纯 CPU 也能跑，但慢 10–30 倍；
- Mac 没有 NVIDIA，走 CPU 或 Apple MPS（Metal），比 4060 慢。

## 能给别人的电脑用吗？

可以，做成 Docker 镜像：`docker load` + `docker run`，浏览器打开即可。
对方需要装 Docker；有 NVIDIA GPU 会快很多，没有则走 CPU。详见
`../docs/08_m4_app.md` 与 `07_running_app.md`。

## 能不能当「自动记谱软件」直接卖？

还不行。当前 onset 很准（留出集 F1 0.87），但**时值还不准**（note-with-offset F1 0.05–0.38），
谱面看起来对、节奏细节不能直接用。下一步要专门修时值。
